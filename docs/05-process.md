# Процесс «Убежища»

Общий порядок работы — устав, [`docs/04-process.md`](https://github.com/Nefeste/gornitsa/blob/main/docs/04-process.md):
документы в репозитории, спецификация до кода, ADR, ветки и CI, кто сливает. Здесь — только то,
что своё у этой игры.

## Версии

- Номер версии — в `app.json` (`expo.version`), `package.json`, `package-lock.json`,
  `src/version.ts` («Об игре») и в первой строке `STATUS.md`. `versionCode` — в `app.json`
  (`android.versionCode`) и `src/version.ts` (`APP_BUILD`). Все сверяет
  `tools/test/version.test.ts`.
- Номер всегда полный, X.Y.Z. До магазина — `0.Y.Z`; первый выход в RuStore — `1.0.0`.
- Третье число — исправление, второе — заметная возможность, первое — смена обещания игроку
  (устав). `versionCode` — +1 на каждую сборку.
- Каждой версии — раздел `### X.Y.Z — …` в «Версиях» корневого `README.md`: что изменилось для
  игрока, человеческим языком. Тот же текст сборка тега кладёт в описание выпуска на GitHub (и
  позже — в «Что нового» RuStore). Тест проверяет, что раздел текущей версии есть.
- Версию поднимает тот PR, который меняет игру для игрока; `app.json` — путь владельца, так что
  такой PR сливает владелец.

## Ветки и слияние

- Работа — в ветке `claude/<задача>`, в `main` — через PR. `main` — всегда то, что можно выпустить.
- На каждом PR — `.github/workflows/pr.yml` («Типы, линтер, тесты»): содержание и типы, линтер,
  тесты. Это обязательная проверка.
- **Кто сливает** (ADR студии 0018): пути из `.github/CODEOWNERS` — `.github/`, `app.json`,
  `src/money/`, `store/` — сливает только владелец. Остальное сливается само
  (`.github/workflows/automerge.yml`, из набора `gornitsa-kit`) после зелёной проверки и метки
  `ревью: ок` от ревьюера из другой сессии; новый коммит снимает метку. Агент никогда не сливает
  сам и не ставит метку на свой PR.
- Тег `vX.Y.Z` ставит владелец (или агент по его слову) на слитый в `main` коммит.

## Сборка APK

`.github/workflows/android.yml` — только по тегу `v*` (ADR студии 0019), без ручного запуска:

1. **Тег и версия** — тег совпадает с `app.json`.
2. **Проверки и сценарий в браузере** — типы, линтер, тесты, веб-сборка, сценарий Playwright.
3. **Сборка APK** — `expo prebuild`, Gradle на arm64-v8a и armeabi-v7a; ключ из секретов
   (`ANDROID_KEYSTORE_BASE64` и другие, вводит владелец), подпись сверяется с
   `ANDROID_CERT_SHA256`; проверки набора: разрешения — только из `.github/apk-permissions.txt`,
   без `INTERNET`, `NETWORK_STATE`, `FOREGROUND_SERVICE`, `WAKE_LOCK`, автобэкап выключен,
   target API ≥ 36, 64-битные библиотеки выровнены на 16 КБ, **размер ≤ 40 МБ**.
4. **Выпуск** — пре-релиз на GitHub с текстом раздела версии из `README.md`, подписью и
   коммитом.

Новое разрешение у библиотеки — сначала `blockedPermissions` в `app.json`; если оно нужно —
строка в `.github/apk-permissions.txt` (путь владельца) и в политике конфиденциальности.

**RuStore** — `.github/workflows/rustore.yml`, только руками: APK из выпуска — в черновик версии;
на модерацию — с отметкой «submit». Первую версию RuStore принимает только через консоль. Нужны
`RUSTORE_API_TOKEN` и `RUSTORE_KEY_ID` (вводит владелец).

## Второй поток: содержание и баланс

Беды, решения, товары и цены — **записи**, а не спецификации ([`09-content.md`](09-content.md)):

1. Запись в `content/` по правилам — с источником, `review: draft`.
2. `npm run content` — сборка и проверка.
3. `npm run sim` — «виртуальный игрок» по всем сочетаниям; отчёт
   `docs/reports/2026-11-virtual-player.md` — в тот же PR, итог — в описание коммита.
4. Если поменялись числа правил — [`08-game-design.md`](08-game-design.md) в том же PR.

## Выпуск

Общая часть чек-листа — устав, `04-process.md`, «Выпуск». Шаги «Убежища»:

1. В `main` всё слито; `npm run typecheck`, `npm run lint`, `npm test`, сценарий в браузере,
   `npm run sim` — зелёные; отчёт свежий.
2. Версия поднята во всех файлах, раздел в `README.md` написан.
3. До первого выпуска в RuStore: все записи `review: checked` (ставит человек), цены Росстата
   сверены с файлом Росстата, название проверено (ФИПС), решены деньги и возрастной рейтинг,
   страница на сайте и раздел в политике конфиденциальности.
4. Тег `vX.Y.Z` → сборка → пре-релиз на GitHub; APK поставлен на телефон и пройден.
5. `rustore.yml` — в черновик RuStore.
6. `STATUS.md` и журнал месяца — в том же или следующем PR.
