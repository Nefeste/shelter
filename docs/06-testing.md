# Проверки «Наготове»

Что запускать перед тем, как сказать «готово», и что проверяет каждая проверка.

## Перед каждым push

```bash
npm run typecheck   # содержание + типы приложения + типы tools/
npm run lint        # ноль предупреждений
npm test            # содержание + bun test tools/test
```

CI запускает то же на каждом PR. Для изменений экранов — ещё сценарий в браузере; для изменений
содержания, цен и движка — ещё «виртуальный игрок».

## Сценарий в браузере

```bash
EXPO_OFFLINE=1 npm run export:web && npm run e2e
CHROMIUM_PATH=/opt/pw-browsers/chromium npm run e2e   # если Playwright проекта не находит свою сборку браузера
```

`tools/e2e/browser.ts` (Playwright, Chromium из среды) проходит путь игрока целиком: первый экран →
вводная → подготовка → 14 дней → итог; перезагрузка страницы — выбор на месте, «Продолжить»;
«Начать заново» с подтверждением; дни дома листаются страницами комикса, «моменты» решаются карточками; хороший план — ★★★; «Переиграть» всем дешёвым — эвакуация и
источник в разборе; дача — ★★★; бревет — четыре страницы КП; велопоход — велосипед с сумками, вес в «Что входит», пять страниц
комикса и «моменты» («Дальше» закрыта, пока не достали нужное), «Мой список» с весом; «Об игре»; «Меньше движения» на первом экране — после перезагрузки на месте, а в браузере с `prefers-reduced-motion` включено само. Ошибка в консоли — провал. Снимки — `tools/e2e/out/` (не в git).
Лист «до — после» для PR с графикой — из этих снимков (устав, [ADR 0023](https://github.com/Nefeste/gornitsa/blob/main/adr/0023-graphics.md);
[`02-architecture.md`, §10](02-architecture.md#10-графика-adr-0023-устава)).

**Проходы по снимкам** — два прохода глазами игрока до того, как звать владельца играть; что
найдено и исправлено — в журнал проверок спецификации.

## Виртуальный игрок

```bash
npm run sim                                   # «Ледяной дождь», около 3 минут
bun tools/sim/player.ts --scenario dacha-new-year   # другой сценарий, отчёт …-virtual-player-<сценарий>.md
bun tools/sim/player.ts --scenario bike-weekend     # велопоход: этапы и сход вместо дней и эвакуации
```

`tools/sim/player.ts` перебирает все сочетания решений: по одному на каждую из начальных бед и на
беды, которые создали выбранные решения (77 824 у «Ледяного дождя»). Каждое проходит подготовку
четырьмя привычками порядка:

- «по списку» — беды по порядку экрана, что не по деньгам или часам — на завтра;
- «с расчётом» — сначала то, что надо успеть до события, и заказы с доставкой, потом по магазинам;
- «наоборот» — с конца списка;
- «дёшево, потом лучше» — в первый день всё дешёвое, потом замена.

Затем — 14 дней на зёрнах 1…30 (столько, чтобы редкие беды — пожар от свечей под присмотром — попадали в замер). Отчёт `docs/reports/2026-11-virtual-player.md` (руками не
править): сколько звёзд у каждой привычки; критерии спецификации («три звезды достижимы», «всё
дешёвое — эвакуация», «нет решения лучше всех», «ловушка не даёт трёх звёзд»); средние звёзды
каждого решения; цена порядка и почему привычка не собрала план; планы на три звезды; разбор на
20 разных итогах — с числом и источником.

**Когда запускать:** любое изменение чисел в `content/`, цен, правил движка — отчёт в тот же PR.

## На телефоне

Бюджет — спецификация прототипа, раздел 8: кадр на целевом телефоне, расчёт 14 дней ≤ 50 мс,
холодный запуск ≤ 3 с, APK ≤ 40 МБ (последнее проверяет сборка тега). Цель кадра — на
современном телефоне, недорогой опорный только запускает игру и проходит её путь (устав,
[ADR 0023](https://github.com/Nefeste/gornitsa/blob/main/adr/0023-graphics.md)); целевой
телефон — Xiaomi 14T владельца, один на все игры студии (Nefeste/uprava#74). Замеры делает владелец, числа — в журнал проверок спецификации. Пока не
сделаны — Nefeste/shelter#18.
